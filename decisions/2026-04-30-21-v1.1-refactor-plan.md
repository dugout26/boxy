# 2026-04-30 — v1.1 출시 후 리팩터링 plan

## Context
시니어 리뷰에서 P2(v1.1) 리팩터링 3건 권장:
1. **VContainer** 도입 — Service Locator 누수 (BoxyBootstrap.Instance.Strings 직접 호출 10+곳) 제거
2. **UniTask** 도입 — 광고/IAP/세이브 비동기 흐름 정리
3. **Addressables** 도입 — Resources/ 폴더 한계 (메모리 + 빌드 사이즈) 회피

v1.0 출시 (2026-05-28)에는 미도입 — 일정 부담 + 리팩터링 risk. v1.1에서 점진 도입.

## Status
v1.0 단계: **준비층(Port + Stub) 작성 완료** — 패키지 미설치 상태에서도 컴파일 가능, 정수가 Unity Editor 활성 후 패키지 설치 + 구현체 교체.

준비된 추상화:
- `Mound.Core.MainThreadDispatcher` — UniTask.SwitchToMainThread 대체, 즉시 사용 가능
- `Mound.Core.IAssetProvider` + `ResourcesAssetProvider` — Addressables 자리 마련, v1.0은 Resources fallback
- `BoxyBootstrap` Service Locator 패턴 — VContainer LifetimeScope로 점진 교체

## Decision
**v1.0**: 인터페이스 + 스텁만. 기능 동일.
**v1.1 (출시 후 1-2주)**: 패키지 설치 + 점진 마이그레이션.

## v1.1 마이그레이션 단계

### 1. UniTask 도입 (1일)
**패키지 설치** (`Packages/manifest.json` 또는 Unity Editor → Package Manager):
```json
"com.cysharp.unitask": "https://github.com/Cysharp/UniTask.git?path=src/UniTask/Assets/Plugins/UniTask"
```

**점진 교체**:
- Step 1: `using Cysharp.Threading.Tasks;` 추가 (선택적 — Task와 동시 사용 가능)
- Step 2: 광고 흐름 `Task<AdResult>` → `UniTask<AdResult>` 교체. 콜백 → await 패턴
- Step 3: IAP `Task<IapPurchaseInfo>` → `UniTask<IapPurchaseInfo>`
- Step 4: 세이브 I/O는 동기 호출이라 변경 X (필요 시 UniTask.RunOnThreadPool로)
- Step 5: `MainThreadDispatcher` 호출을 `UniTask.SwitchToMainThread()`로 교체

**우선 대상 파일**:
- `Mound.Monetization.IAdProvider` (Task → UniTask)
- `Mound.Monetization.IIapProvider`
- `Mound.Monetization.IConsentProvider`
- `Mound.Monetization.IReceiptValidator`
- `Boxy.App.Gameplay.HintAdController` / `UndoAdController` / `AdRewardFlow`
- `Boxy.App.BoxyBootstrap.RequestConsentDelayedAsync`

### 2. Addressables 도입 (2-3일)
**패키지 설치**:
```json
"com.unity.addressables": "2.6.0"
```

**점진 교체**:
- Step 1: Unity Editor → Window → Asset Management → Addressables → Groups 메뉴에서 Addressables 활성화
- Step 2: `Assets/Boxy.App/Resources/Mascot/*.png` 6장을 Addressables Group `Mascot`으로 이동
- Step 3: 마찬가지로 `Icons/`, `Audio/`, `Levels/` 점진 전환
- Step 4: `BoxyBootstrap`의 `IAssetProvider` 등록을 `ResourcesAssetProvider` → `AddressablesAssetProvider`로 교체
- Step 5: `ResultPopupController.cs:132` Resources.Load → `assetProvider.LoadAsync<Texture2D>($"Mascot/{expression}")` 교체

**측정 기대치**:
- APK 사이즈 -10~30% (사용 안 하는 asset Group 분리 + 다운로드 분리)
- 메모리 -20% (Resources.UnloadUnusedAssets 일괄 정리 → Addressables.Release per-asset)

### 3. VContainer 도입 (3-5일, 가장 큼)
**패키지 설치**:
```json
"jp.hadashikick.vcontainer": "1.16.0"
```

**점진 교체** (Service Locator 누수 제거):
- Step 1: `Boxy.App/Composition/RootLifetimeScope.cs` 신규 — VContainer LifetimeScope MonoBehaviour
- Step 2: `BoxyBootstrap` Provider 인스턴스화를 LifetimeScope.Configure(IContainerBuilder builder)로 이전:
  ```csharp
  builder.Register<ISaveSystem, PlayerPrefsSaveSystem>(Lifetime.Singleton);
  builder.Register<IStringTable, KoEnStringTable>(Lifetime.Singleton);
  builder.Register<IAdProvider, NullAdProvider>(Lifetime.Singleton);
  // ...
  ```
- Step 3: Controller 생성자 주입 도입:
  ```csharp
  public class MainMenuController : MonoBehaviour {
      [Inject] readonly IStringTable strings;
      [Inject] readonly ISceneLoader sceneLoader;
      // BoxyBootstrap.Instance 호출 모두 제거
  }
  ```
- Step 4: 씬별 LifetimeScope (예: `GameplayLifetimeScope`) — 게임플레이 전용 의존성 (PlacementValidator 등)
- Step 5: `BoxyBootstrap.Instance` 정적 참조 모두 제거 — 컴파일 타임 검증

**기대 효과**:
- BoxyBootstrap 비대 제거 (현재 ~150줄 Provider 인스턴스화 → ~20줄 entry point)
- 단위 테스트 mock 주입 자유로움
- 씬/레벨별 LifetimeScope 분리 (메모리 격리)

## Consequences
좋은 것:
- VContainer: 트렌드 정합성 + 테스트 가능성 + Service Locator 누수 제거
- UniTask: 비동기 흐름 명확 + GC alloc 감소 + try/catch 가독성
- Addressables: 빌드 사이즈 절감 + 동적 컨텐츠 (시즌 한정 스킨 등) 가능

나쁜 것 / 위험:
- 패키지 추가 → APK 사이즈 +5~10MB (UniTask + Addressables + VContainer 각 1-3MB)
- 학습 비용: VContainer 반나절, UniTask 1시간, Addressables 2-3일
- 출시 직전 도입 시 회귀 버그 위험 → **반드시 v1.1로 미루기**

## Revisit when
- 출시 후 D7 retention < 8% → 우선순위 하락 (Boxy Sort 즉시 착수)
- D7 ≥ 10% → v1.1 1주 작업으로 진행
- ARPDAU $0.15+ → 자체 서버 IAP 검증 + Addressables 클라우드 컨텐츠 (시즌 패스) 동시 검토
