## Phase별 핵심 결정

| Phase | 결정 | 이유 |
|---|---|---|
| **P3** | accent를 게임별 USS로 분리 (`accent-boxy.uss`) | tokens.uss 재사용성, 게임마다 #FFD60A 외 색상 가능 |
| **P4-A** | Vector2Int 사용 (자체 GridCoord X) | Unity 직렬화 + 연산자 빌트인 |
| **P4-A** | ItemShape 불변 readonly struct + Rotate 후 Normalize | 모양 동일성 비교 가능, race condition 회피 |
| **P4-A** | string itemKey (Boxy.App 도메인) | 단순. v1.1에서 ItemId struct로 wrap 가능 |
| **P4-B** | PlacementValidator static class + PlacementResult enum | 상태 없는 순수 함수, BoxyGrid.Place는 사전 검증 의존 |
| **P4-C** | 거꾸로 생성 + 1×1 fallback | 100% 풀 수 있는 레벨 보장 (boxy-plan §B-3-2) |
| **P4-D** | UndoSystem AnyConsumed 플래그 | boxy-plan §B-2-1 별 시스템 단순 부울 체크 |
| **P5** | tokens.uss에서 accent 제거, 게임이 강제 override | 디자인 시스템 청결성 |
| **P5-B** | accent-boxy.uss에 게임별 컴포넌트 (level-button, theme-tab) | level-button 원형은 Boxy 고유 |
| **P6-B** | NullAdProvider Editor 스텁 (Task.Delay 1s → Rewarded) | 라이선스/실 SDK 없이도 Editor 흐름 검증 가능 |
| **P6-B** | TestAdIds 정적 클래스 (Google 공식 테스트 ID) | dev/stg에서 실 ID 정책 위반 회피 |
| **P7** | UIDocument.rootVisualElement.Q<T>(name) 캐싱 패턴 | UI Toolkit 표준 |
| **P7** | EventBus 인스턴스를 GameplayUI가 생성, Controller에 주입 | Phase 8 이후 UI 외 시스템과 공유 가능 |
| **P8** | UI Toolkit Manipulator + schedule.Execute 길게 누르기 | boxy-plan §B-2-3 명시 |
| **P8** | ItemCardView를 static factory → VisualElement 서브클래스 | 회전 상태 보존 + 자체 manipulator |
| **P8** | 드래그 거리 8px 임계 / 길게 누르기 0.5s 임계 | 표준 모바일 UX |
| **P9** | HintAdController/UndoAdController는 Boxy.App에 위치 | Mound.Monetization은 게임 의존 X (§5-3) |
| **P9** | async void 회피 → `_ = HandleXxxAsync()` 패턴 | CLAUDE.md §11-2 명시 |
| **P10** | SceneLoader 인터페이스 + 구현 분리 | DI 가능, NullSceneLoader 테스트 stub 가능 |
| **P10** | BoxySceneNames를 Mound.Core에서 제거 | §5-1 모듈 경계 — 게임 의존 코드는 Boxy.App에 |
| **P10** | NullAnalyticsProvider | dev/Editor에서 실 Firebase 없이 통합 흐름 검증 |

## Consequences

### 좋은 것
- **모듈 5개로 분리** — Boxy Sort/Cafe 신규 게임 시 `Boxy.App.asmdef`만 갈아끼움
- **모든 외부 SDK가 인터페이스 뒤** — IAdProvider/IIapProvider/IAnalyticsProvider/ISceneLoader 모두 추상화 (§5-3)
- **정적 검사기가 5건의 진짜 위반 자동 검출** — CLAUDE.md §19 기술적 강제 실효성 입증
- **결정 기록 7개 누적** — Phase별 추적 가능

### 나쁜 것 / 위험
- **컴파일 검증 0회** — Unity 라이선스 미활성. Hub OAuth 후 일괄 검증 시 USS/Manipulator 등 일부 에러 가능
- **NullAdProvider/NullAnalyticsProvider stub** — 실 SDK 통합 전엔 KPI 측정 X
- **Phase 9까지 진행했는데 실제 Unity Editor에서 실행 한 번 못 해봄** — 5/12 클로즈드 테스트 빌드 업로드까지 13일 남음
